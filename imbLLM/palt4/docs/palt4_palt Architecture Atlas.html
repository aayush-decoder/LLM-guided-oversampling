palt Architecture Atlas

Four repositories, two replicated papers and one new method. palt, palt2 and palt3 replicate and correct two LLM oversamplers. palt4 builds TILT on top of them: a thesis method that generates the minority rows the classifier needs. For each version: how a table becomes text, how a language model is fine-tuned on it, how new rows come out, what that does for the minority class, and what each version got wrong or right. Nothing here has been trained yet; this describes the code, its checks, and the published numbers.

palt/
Pred-LLM replication and an improved generator
v1 (paper) · v2 (N1–N5). Base: Nguyen et al., ICDM 2024, arXiv 2410.21717. Whole-table synthesis; not an imbalance method.
palt2/
ImbLLM replication, first pass, with an audit
v1_replication · v2_improved (flags + presets). Base: ImbLLM, arXiv 2510.09783. Superseded by palt3.
palt3/
ImbLLM replication, corrected, with attributable flags
v1_paper · v2_corrected (presets v1_exact, recommended, geometry_only, full) + baselines. The corrected harness.
palt4/
TILT: task-informed LLM tilting (the thesis)
palt3's core, plus a KL-budgeted, utility-tilted sampler (SIR or field-wise twisted SMC), a validity floor, a privacy cap, theory checks and a no-LLM oracle study. Qwen3 ladder, 0.6B–32B.
fast test suites pass palt4: 6/6 theory checks pass GPU / LLM tests not run no experiment results in any repo

02The two base papers

Both papers belong to the GReaT family: write each row as a sentence, fine-tune a causal language model on the sentences, then let it write new sentences and parse them back into rows.

shared idea · serialisation and fine-tuning
\[ t(x,y) = \text{"}X_{\pi(1)} \text{ is } v_{\pi(1)},\ \dots,\ X_{\pi(M)} \text{ is } v_{\pi(M)},\ Y \text{ is } y\text{"} \qquad \min_\theta\; -\sum_{s \in \mathcal{D}'}\sum_{t} \log p_\theta(s_t \mid s_{<t}) \]
\(\pi\) is a random ordering of the columns; \(s_t\) are the tokens of one sentence.

Pred-LLM (ICDM 2024)

  • Encoding. Categories become integer codes, every column is MinMax-scaled to [0, 1] and rounded to 2 decimals.
  • Permute features only. The target stays last. Training uses permuted rows plus the original order: \(\mathcal{D}' = \mathcal{D}_\pi \cup \mathcal{D}\).
  • Feature-conditional sampling. \(n/M\) prompts per feature, each starting "\(X_i\) is \(v\)" with \(v \sim \hat p(X_i)\). Temperature \(T = 0.7\).
  • Label querying. The generated \(x\) is re-written in the original order and the same model is asked for "target is ?".
  • Evaluation. Train on synthetic, test on real (TSTR) with XGBoost.

ImbLLM (arXiv 2510.09783)

  • Target. Learn \(p(x \mid y_{\min})\) from a small minority set and generate \(\hat n = |\text{largest class}|\) minority rows.
  • C1, conditioning. Prompt "\(Y\) is \(y_{\min}\), \(X_i\) is \(v\)," with \(i \sim \mathcal{U}\{1..M\}\), \(v \sim p(X_i)\).
  • C2, order. \(Y\) is fixed first; the features are shuffled.
  • C3, corpus. Fine-tune only on minority rows plus interpolated ones: \(x' = x_i^{\text{con}} + \varepsilon\,(x_j^{\text{con}} - x_i^{\text{con}})\), \(\varepsilon \sim \mathcal{U}(0,1)\), \(j\) a random minority row.
  • Evaluation. XGBoost trained on \(\mathcal{D}_{\text{major}} \cup \hat{\mathcal{D}}_{\text{minor}}\), minority F1 and AUC on real test rows.

03The imbalance setup, and the baseline every method must beat

palt2 and palt3 follow ImbLLM's protocol. The real minority set is shrunk on purpose, so the problem is hard enough to need help.

protocol
\[ \mathcal{D}^*_{\text{train}} = \mathcal{D}_{\text{major}} \cup \mathcal{D}^*_{\text{minor}}, \qquad \mathcal{D}_{\text{minor}} = q \cdot \mathcal{D}^*_{\text{minor}}\ (q = 0.2), \qquad \hat n = |\text{largest class}| \]
The generator may see \(\mathcal{D}_{\text{major}} \cup \mathcal{D}_{\text{minor}}\) only. The other 80% of real minority rows are held out for quality checks.

There are three ways to fix imbalance without generating anything. palt3 runs all three as references:

\[ \underbrace{\hat y = y_{\min} \iff p(y_{\min}\mid x) \ge t^*}_{\text{threshold, } t^* \text{ tuned on a real validation fold}} \qquad \underbrace{\hat y = \arg\max_k \frac{p(k \mid x)}{\pi_k}}_{\text{prior shift (Elkan 2001)}} \qquad \underbrace{w_{\min} = \hat n / n_{\min}}_{\text{class weights}} \]
Why this matters for every generator below. If a generator produced perfect minority rows, \(\hat x \sim p(x \mid y_{\min})\), a well-fitted classifier would only see its minority prior odds multiplied by \(\frac{n_{\min} + \hat n}{n_{\min}}\). That is exactly a threshold move. So in the large-data limit, perfect oversampling equals a tuned threshold. A generator only earns its cost if it beats threshold_only. That extra gain can only come from finite-sample smoothing, knowledge the LLM brings from pre-training (or memorisation), or a useful tilt in what it generates.

v1: Pred-LLM as published

Shared modules in common/tabgen: data (registry, download, preprocess), llm (registry, loader, weighted train loop), eval (TSTR, fidelity, tables), baselines (SDV CTGAN / TVAE / CopulaGAN), viz, audit, experiment. On top of that, v1 adds a serialiser, a dataset of permuted sentences, a sampler, a label querier and eight presets. Those presets are GReaT, TapTap and the six Table III ablations, all on one pipeline.

v2: five changes, N1 to N5

N3 · weighted value-only loss
\[ \mathcal{L} = -\frac{\sum_t w_t \log p_\theta(s_t \mid s_{<t})}{\sum_t w_t}, \qquad w_t = \begin{cases} 0 & \text{column-name scaffold ("age is")} \\ \lambda = 3 & \text{target value} \\ 1 & \text{other values and the terminator} \end{cases} \]
N2 · exact categorical choice and constrained numbers
\[ P(v \mid \text{prefix}) \propto \Big(\prod_{t} p_\theta(\text{tok}_t(v) \mid \dots)\Big)^{1/T}, \qquad \text{logit}_k \leftarrow -\infty \text{ if token } k \text{ breaks the number grammar} \]
N4 · label averaged over orders · N5 · curation
\[ \bar p(y \mid x) = \frac1R \sum_{r=1}^{R} p_\theta(y \mid x; \pi_r) \qquad r(x) = \frac{n_{\text{syn}}}{n_{\text{real}}}\cdot\frac{D(x)}{1 - D(x)},\ \ w = \operatorname{clip}(r, \tfrac1c, c)^{\beta} \]
N1 is raw values instead of codes. N5 also drops rows closer to a training row than the \(\alpha\)-quantile of real holdout distances (DCR gate).

Done right

  • The Pred-LLM protocol is reproduced exactly, including the authors' scaler fitted on the full data.
  • Rows stop at EOS. Start tokens use the same number format as the training text.
  • A fine-tune cache is shared across presets. Full / LoRA / QLoRA switch, byte-level BPE models only.
  • v2 makes every generated value valid by construction, and keeps integer columns integer (decimals inferred as 0).

Flaws

  • Leaky protocol (kept on purpose to match the paper). The scaler is fitted on train + test.
  • Category codes are natural-sorted. Ordinal order is lost, and nominal categories get fake distances.
  • Circular v2 score fixed 28 Sep. v2's curation used the same kind of discriminator, on the same training rows, as the fidelity score.
  • cardio leaks its label fixed 28 Sep. V26–V35 one-hot encode the class, which explains the paper's 1.0000.

Novelty vs the paper

  • Each of N1–N5 exists in prior work: REaLTabFormer token masks, TabularMDLM, permutation self-consistency / TabPFN, Grover 2019 / CLLM.
  • What is new is the combination, applied inside a Pred-LLM-style generator. A method paper would need to beat TabSyn / TabDDPM / CLLM.

Caveats

  • Not an imbalance method. Label sampling at \(T_y = 0.7\) shrinks rare labels: \(0.05 \to 0.05^{1/0.7}/Z \approx 0.015\).
  • The v1/v2 unit and smoke tests need torch and have not been run.
  • The paper rule "accuracy = 0 if a class is missing" makes small-class failures look catastrophic rather than graded.

05palt2 · ImbLLM, first pass

imbcore (shared) · v1_replication · v2_improved · audits/cli.py · AUDIT.md · 10 datasets

imbcore holds the datasets, a 3-verb LLM engine (finetune, complete, score_conditional), classical baselines, evaluation and stats. v1_replication implements C1/C2/C3 as published. v2_improved wraps each audit finding in a flag and groups the flags into presets: v1_exact, recommended, geometry_only and full.

the audit's three central derivations (correct, and carried into palt3)
\[ \operatorname{Cov}(x') = \mathbb{E}\big[(1-\varepsilon)^2 + \varepsilon^2\big]\,\Sigma = \tfrac23\,\Sigma \qquad w(v) = \frac{p(v)}{p(v \mid y_{\min})} \qquad \frac{|\mathcal{D}_{\text{inter}}|}{|\mathcal{D}_{\text{inter}}| + |\mathcal{D}_{\text{minor}}|} = \Big(1 + \frac{q}{\rho}\Big)^{-1} \ge 94\% \]
1. Random partners shrink the spread. 2. Pooled conditioning values tilt the minority towards majority-typical values by the Bayes likelihood ratio. 3. The fine-tuning corpus is almost all interpolated rows, which carry no categoricals.

What it got right

  • Found the \(\tfrac23\Sigma\) contraction, the ~35% off-manifold interpolants on a bimodal minority, the pooled-marginal tilt, and the 94% categorical-free corpus.
  • Framed random-order fine-tuning as a dependency network (Heckerman 2000) and proposed measuring order sensitivity.
  • Added the missing threshold_only and scale_pos_weight baselines, and ran statistical tests on the published table.
  • Documented where the paper's Table I differs from the public datasets.

Flaws (from palt2/AUDIT.md)

  • GPU training could not work. fp16 weights plus a GradScaler raise "Attempting to unscale FP16 gradients".
  • Token-level problems. Left padding in training, no EOS, prompts ending in ", ", and scoring by the mean over a whole clause.
  • Parser problems. Yield divided by rows requested. An empty category snapped to the first category. Splitting on every comma broke values that contain commas.
  • Gibbs was not Gibbs. It conditioned on the preceding prefix only, with one shared pool of 8 values.
  • Other v2 fixes were flawed too. \(\tau = 0\) still drew majority-shaped values inside each bin. kNN searched raw units. Interpolated rows took categoricals from random donors.
  • Reporting. Two Table II transcription typos, and an "identity check" that was a tautology.
  • Hidden protocol change. recommended flips 6 flags at once, including a protocol change, so gains cannot be attributed.

Novelty vs the paper

  • The \(\tau\)-bridge, which turns the accidental tilt into a knob: \(p_\tau(v) \propto p(v\mid y_{\min})^{1-\tau} p(v)^{\tau}\).
  • The fidelity–diversity frontier and the entropy identity \(\Delta H = I(G;R) - \delta\) (known maths, new use).
  • A negative result: local variance-preserving kNN is indistinguishable from plain kNN.

Caveats

  • Never produced a result. Any GPU number would have been a crash, or rows from mis-tokenised prompts.
  • Numbers were rounded to 2 decimals, and "numeric with more than 12 levels" meant continuous, which mistyped some columns.
  • Frozen. Cite its audit as the source of palt3's fixes.

\[ \begin{aligned} &\textbf{B1 geometry:} && x' = x_i + \varepsilon(x_{\text{NN}_k(i)} - x_i),\ \text{neighbours in z-space} \ \Rightarrow\ \operatorname{Cov}(x') \approx \Sigma,\ 0\%\ \text{off-manifold} \\ &\textbf{B2 tilt:} && p_\tau(v) \propto p(v \mid y_{\min})^{1-\tau}\, p(v)^{\tau},\ \text{exact at } \tau \in \{0, 1\},\ \text{KDE in between} \\ &\textbf{B3 categoricals:} && x'^{\text{cat}} = x_i^{\text{cat}} \ (\text{the anchor's, not a random donor's}) \\ &\textbf{B4 consistency:} && x_j \sim p_\theta(x_j \mid y, x_{-j}),\ \text{continuous by SIR with weight } p_\theta(v\mid\cdot)/q_{\text{KDE}}(v) \\ &\textbf{B4 measure:} && \sigma = \operatorname{mean}_{x}\ \operatorname{std}_{\pi}\big[\log p_\theta(x \mid y; \pi)\big] / T_x,\ \text{vs the same on real held-out rows} \end{aligned} \]

What it corrected

  • 16 engineering fixes. Precision, padding, EOS, prompt tokenisation, summed scoring, yield, repair, comma sanitising, 5 significant digits, config precedence, stale metrics, model cache, one runner.
  • 9 protocol fixes.
    • Every method is scored with its own decision rule.
    • A real validation fold is used for threshold tuning.
    • The quality metric uses one fixed metric space, reported both against the paper's reference set and against held-out rows.
    • Regression targets are binarised at a train-split quantile.
    • Multiclass datasets use a K-way classifier.
    • Failed methods are ranked last instead of dropped.
    • Holm-corrected tests, and the corrected Table II.
  • Added 28 Sep. Four learners, 10 seeds, contamination probes, a cost column, dataset covariates, CLLM curation, TabDDPM / ARF, an order-sensitivity reference, and integer / ordinal column handling.

Remaining flaws

  • v1_paper still writes fractional counts and ignores ordinal order. That is faithful to the paper; v2's snap_discrete and ordinal_interpolation fix both.
  • Ordinal orders are declared only for car and gem_price, and are not yet checked against the downloaded files.
  • The GReaT / TapTap / Pred-LLM baselines are re-implementations on this engine.
  • TabSyn, TabDiff, TabEBM and EPIC are not included.

Novelty vs the paper

  • A critical replication: ImbLLM has no public code.
  • The order-sensitivity measurement, which appears new for GReaT-style models.
  • The cardio leak diagnosis.
  • A corrected ablation reading: minority-only fine-tuning carries +0.068. x-conditioning adds +0.058, but only together with it.
  • No new theorems. The \(\tau\)-bridge, SIR-Gibbs and kNN geometry are known constructions.

Caveats

  • Nothing has been trained. The smoke setting (60 epochs on a tiny model) is unverified, and so is the synthcity adapter.
  • Train/test duplicate rows: adult 735, compas 105, kc1 84.
  • The clean protocol trains on 72% of the data, not 80%.
  • With 3 datasets, a Wilcoxon test can never reach \(p < 0.05\). Use at least 6 datasets.

07palt4 · TILT, the thesis method

src/tiltgen: methods/tilt (utility · tilt · privacy · partial · smc · method) on palt3's core · experiments/oracle · audits/theory_checks · CLI tilt

palt3 answered "is ImbLLM correct?". palt4 asks the next question: which synthetic rows help at all, given that a tuned threshold is free? TILT keeps palt3 v2's generator, with the same corpus and the same cached fine-tune, and replaces only the sampling stage. Every TILT knob is sampling-only, so one fine-tune per (dataset, seed) serves every experiment arm.

the four propositions (docs/THEORY.md), each checked by tilt audit theory
\[ \begin{aligned} &\textbf{Prop 1:} && \frac{\eta'}{1-\eta'} = \Big(1+\tfrac{m}{n_{\min}}\,r(x)\Big)\frac{\eta}{1-\eta},\quad r=\tfrac{q}{p_{\min}} \;\Rightarrow\; \text{no } q \text{ beats } \sup_t \mathrm{M}(\mathbb 1[\eta>t]) \text{ at population level} \\ &\textbf{Prop 2:} && \Delta R = -\varepsilon\,\mathbb E_q[u] + O(\varepsilon^2),\quad u_2(x)=\sigma(1-\sigma)\,\tilde x^\top H^{-1}H_{\text{val}}H^{-1}\tilde x \;\Rightarrow\; q^\star \propto p\,e^{\lambda u}\ \text{under}\ \mathrm{KL}(q\|p)\le\varepsilon \\ &\textbf{Prop 3:} && \log w_t \mathrel{+}= \log\psi_t(x_{1:t})-\log\psi_{t-1}(x_{1:t-1}),\quad \log\psi_T=\lambda z(x)\ \Rightarrow\ \text{exact for any positive twist} \\ &\textbf{Prop 4:} && \text{record amplification} \le e^{\lambda\,\mathrm{range}(z)} \;\Rightarrow\; \lambda \le \log A/\mathrm{range}(z) \end{aligned} \]
Corollary: with \(u=\log p_{\text{LM}}(x\mid y_{\text{maj}})-\log p_{\text{LM}}(x\mid y_{\min})\), the tilt equals sequence-level classifier-free guidance \(p_{\min}^{1-\lambda}p_{\text{maj}}^{\lambda}\).

Done right

  • It starts from the honest baseline. Prop. 1 shows that no oversampler beats a tuned threshold at population level, so every result is reported as a gain over threshold_only, for 4 learners.
  • The utility is derived, not heuristic. The default Fisher-leverage \(u_2\) targets reducible variance. The aleatoric utility is a named ablation predicted to hurt, which answers the label-noise objection up front.
  • The theory is checked by code:
    • intercept shift 2.96 vs the predicted 2.996;
    • first-order law: correlation 0.997 at ε = 0.002;
    • SMC matches the target distribution (TV 0.021).
  • Tests caught real weaknesses before any GPU hour was spent:
    • a linear validity probe fails on a bimodal minority (57% of majority rows passed), so it is now non-linear;
    • a wide-bandwidth attack missed exact copies (AUC 0.59), so the attack is now distance-based;
    • a seed-sharing artefact in the SMC check.
  • Sampling-only design: one fine-tune serves every utility, budget and sampler arm.

Weaknesses and open issues

  • Prop. 2 is first-order. At balancing scale (ε = 0.05) its prediction saturates (slope 0.18). The KL budget is the fix, but the optimal ε must be found empirically.
  • Fisher / influence use a linear probe. On multi-modal minorities its notion of "boundary" is crude.
  • SIR selects without replacement from a finite pool, which is only an approximation of \(q^\star\). SMC de-duplication slightly flattens \(q^\star\) on all-categorical tables.
  • SMC costs about (N/keep)·(M+1) field calls per row. Wide tables (ozone, 72 features) are SIR-only.
  • First oracle trial (3 seeds, n_min = 20): perfect untilted oversampling reached +0.024 over the threshold, and no tilt beat it yet (+0.005 to +0.018). This is not conclusive, but it is a warning.

Novelty vs the base papers and the literature

  • New combination: a KL-budgeted utility tilt with a validity floor and a privacy cap, for LLM tabular oversampling. The closest prior work is Askari-Hemmat et al. (TMLR 2024): the same tilt for image diffusion, with no budget, no SMC and no privacy.
  • New application: field-wise twisted SMC with a partial-row twist (FUDGE for fields). No tabular use was found.
  • New: Prop. 2 (optimal placement), the CFG-as-tilt corollary, and the amplification bound. Prop. 1 is a new assembly of known results (Elkan, Koyejo et al.).
  • Known parts, cited: the Gibbs principle, twisted SMC, TERM, and Nakada et al.'s θbal result.

Caveats

  • No LLM training and no real-table results yet. H1–H8 in docs/EXPERIMENTS.md are hypotheses with falsification conditions.
  • The torch tests (pytest -m llm, tilt smoke) are written but have not run on this machine.
  • The natural tables' shapes and targets come from the OpenML API. They have not been fetched and verified locally.
  • If E0 or E1 comes out negative, the thesis becomes a well-founded "when and why guidance does not help" (docs/THESIS.md, risks).
